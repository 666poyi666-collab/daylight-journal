# 用户需求基线

本文档把产品愿景转换为可编号、可验收、可追踪的需求。产品边界以
`PRODUCT.md` 为准，技术实现以 `ARCHITECTURE.md` 为准。需求发生变化时，先更新本文，
再修改代码。

## 用户与场景

主要用户是希望低摩擦记录和长期复盘的个人用户。典型场景包括手机随手记录、平板或
电脑补充长文、跨设备回看，以及主动把当天记录交给 ChatGPT 复盘。

## 功能需求

| 编号 | 需求 | 验收条件 | 状态 |
| --- | --- | --- | --- |
| FR-001 | 快速开始当天记录 | 打开应用默认进入今天；标题或正文输入后立即形成记录 | 已完成 |
| FR-002 | 本地自动保存 | 每次编辑立即写本地；刷新、离线或同步失败后草稿仍在 | 已完成 |
| FR-003 | 多记录片写作 | 同一天可新建、排序和删除多个记录片，旧数据可确定性迁移 | 已完成 |
| FR-004 | 写作会话时间 | 每片保存开始与停笔时间，阅读态按正文偏移显示时间 | 已完成 |
| FR-005 | 轻量格式 | 支持 Markdown 加粗、斜体和三档整片文字颜色 | 已完成 |
| FR-006 | 情绪与标签 | 心情和标签均可选，不以完成度强迫填写 | 已完成 |
| FR-007 | 单图封面 | 每篇最多一张压缩图片；无图时仍以文字为主 | 已完成 |
| FR-008 | 日期与历史回看 | 支持日历、搜索、月份时间流和往年今日 | 已完成 |
| FR-009 | 跨端同步 | 从共享副本拉取并按日期修订合并；失败不阻塞本地写作 | 已完成，存在 KR-001 |
| FR-010 | AI 只读复盘 | 保存并同步当前修订后复制提示词、打开 ChatGPT，由 MCP 只读获取记录 | 已完成 |
| FR-011 | Markdown 导出 | 用户可导出全部记录，正文不被 AI 自动改写 | 已完成 |
| FR-012 | 服务配置 | 公网同步地址和 ChatGPT 项目通过构建环境显式配置，不进入公开源码 | 已完成 |

## 非功能需求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| NFR-001 | 隐私 | Git 历史不含真实日记、令牌、Cookie、个人 Tunnel 或完整运行日志 |
| NFR-002 | 可靠性 | `npm run build`、Lint、单元测试通过；离线刷新恢复本地草稿 |
| NFR-003 | 响应式 | 390×844、768×1024、1024×768、1440×900 核心页面无重叠和横向溢出 |
| NFR-004 | 可访问性 | 关键目标至少 44px、焦点可见、表单有名称、减少动效模式可用 |
| NFR-005 | 兼容性 | Web/PWA 与 Capacitor Android 共用数据模型和主要交互 |
| NFR-006 | 可维护性 | 需求、架构、接口、Bug、变更和视觉决策各有唯一文档归属 |

## 明确不做

- 第一阶段不接 OpenAI API、Time One 或滴答清单。
- 不做社交发布、账号系统、复杂富文本或自动改写原文。
- 不做 Obsidian 双向写入；当前只提供 Markdown 导出。
- 不宣称当前同步支持 block 级实时协作或无冲突合并。

## 需求变更流程

1. 用 `FR-xxx` 或 `NFR-xxx` 描述用户结果和验收条件。
2. 在 `PRODUCT.md` 确认是否属于当前阶段。
3. 实现时更新对应架构、同步或视觉文档，并补测试。
4. 修复缺陷时登记 `BUGS.md`；用户可感知变更登记 `CHANGELOG.md`。
5. 合并前按 `DEVELOPMENT.md` 完成验证，不以聊天记录替代项目事实。
